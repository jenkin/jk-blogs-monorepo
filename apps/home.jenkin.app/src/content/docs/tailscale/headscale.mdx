> Headscale's goal is to provide self-hosters and hobbyists with an open-source server they can use for their projects and labs.
> It implements a narrow scope, a single Tailscale network (tailnet), suitable for a personal use, or a small open-source organisation.

I'm going to use a [VPS NL-1](https://mynymbox.net/vps) by MyNymBox, so 1 vCPU, 512 MB of RAM, 10 GB of disk, and 1 TB of traffic per month.
Headscale should only coordinate nodes, so these requirements should be sufficient for tens or few hundreds of nodes.

## Getting started

My operating system of choice is [GNU/Linux Debian 13 Trixie](https://www.debian.org/releases/trixie/release-notes/index.en.html).
I suggest to update the system at the very first login: `apt update && apt dist-upgrade`.

### SSH client

First of all, save server details in SSH config on your computer.

```txt title="~/.ssh/config"
Host *
    ServerAliveInterval 30

Host hs.remote
    HostName X.X.X.X
    User root
    Port 22
```

Then enable SSH login via public key with `ssh-copy-id hs.remote` and now you can connect simply using `ssh hs.remote`.

### SSH server

Changing SSH port is a best practice to avoid malicious bot traffic.
On the server edit the SSH server config in `/etc/ssh/sshd_config`.

```txt title="/etc/ssh/sshd_config"
# A random port number between 1024 and 65535
Port 49876
# Disable password login, use only public key
PermitRootLogin prohibit-password
```

Restart SSH server with `systemctl restart sshd` and terminate connection.

Change host port in your `~/.ssh/config` and login again.

<Aside type="tip">
    If you have trouble logging in again, please double check the port and check if your VPS provider has a firewall active.
    If so, allow the new SSH port and remove the rule for the old one.
</Aside>

## Installation

We need two services: [Headscale](https://headscale.net/stable/) and [Caddy](https://caddyserver.com/).

### Headscale

The default and recommended way to install headscale is using official `.deb` packages
(see the [official documentation](https://headscale.net/stable/setup/install/official/#using-packages-for-debianubuntu-recommended)).

<Steps>
    1. Run `apt install -y curl wget apt-transport-https`
    2. Set environment variables
        ```shell
        HEADSCALE_VERSION="0.27.1"
        HEADSCALE_ARCH="amd64"
        ```
    3. Download the package: `wget -O headscale.deb "https://github.com/juanfont/headscale/releases/download/v${HEADSCALE_VERSION}/headscale_${HEADSCALE_VERSION}_linux_${HEADSCALE_ARCH}.deb"`
    4. Install it: `dpkg -i ./headscale.deb`
    5. If needed, install missing dependencies: `apt install -f`
</Steps>

### Caddy

Headscale has to be publicly reachable by nodes, so we need to expose it to external traffic via https.
We will use Caddy as reverse proxy and to automatically manage TLS termination (see the [official documentation](https://caddyserver.com/docs/automatic-https)).

Install it from official repository: `apt install caddy`.

<Aside>
    You can also use the official third-party repository for the latest releases.
    See the [official documentation](https://caddyserver.com/docs/install#debian-ubuntu-raspbian) for further details.
</Aside>

## Configuration

### Headscale

Main configuration is stored in `/etc/headscale/config.yaml` file.

```yaml title="/etc/headscale/config.yaml"
# Public domain, you need to register it and control the DNS
server_url: https://hs.yourdomain.app
dns:
    # If you want to use domain names such as headscale.home.yourdomain.app
    # for your nodes inside the tailscale network instead of 100.64.0.X
    magic_dns: true
    # You can use any valid domain name, not related to your server_url
    base_domain: home.yourdomain.app
    override_local_dns: true
```

Now apply the new configuration: `systemctl enable --now headscale`.
Check if headscale daemon is running as expected: `systemctl status headscale`.

Create the user the network nodes will belong to: `headscale users create your_name`.
Check if it exists: `headscale users list`.

### Caddy

Edit the configuration file: `/etc/caddy/Caddyfile`.

```txt title="/etc/caddy/Caddyfile"
hs.yourdomain.app {
    reverse_proxy 127.0.0.1:8080
}
```

Apply the new configuration: `systemctl restart caddy`.

### DNS

Your domain need to be resolved to your VPS's public IPs (IPv4 and IPv6), so you need to add these DNS records for `yourdomain.app`.

```
A    hs X.X.X.X
AAAA hs X:X:X:X::X
```

Now a request sent to `https://hs.yourdomain.app` is managed by Caddy on your VPS:
automatic TLS certificates management, TLS termination, reverse proxy to headscale.

<Aside>
    Headscale service is intended to be used by nodes, so no web page is exposed on root path.
</Aside>

## Final steps

SSH server needs custom port 49876, caddy needs public ports 80 (http) and 443 (https),
tailscale needs port 41641 for udp traffic.

Setup a firewall that closes all ports but those really needed is strongly suggested.

<Steps>
    1. Install ufw: `apt install ufw`.
    2. Deny all incoming traffic: `ufw default deny incoming`
    3. Allow all outgoing traffic: `ufw default allow outgoing`
    4. Open custom SSH port: `ufw allow 49876/tcp` (double check the port!)
    5. Close default SSH port: `ufw deny 22/tcp`
    6. Open http port: `ufw allow 80/tcp`
    7. Open https port: `ufw allow 443/tcp`
    8. Open headscale udp port: `ufw allow 41641/udp`
    9. Apply new rules: `ufw --force enable`
</Steps>

<Aside>
    If your VPS provider has a firewall active, replicate the ufw configuration on it.
</Aside>
